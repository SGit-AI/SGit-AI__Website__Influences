The network

This site is one of several that carry one argument between them. Each is a separate repository, a separate domain and a separate release history — and each is built from the same three pieces: a commissioning brief published in full, a static site written from it, and the validate → tag → deploy pipeline that gates every release.

What is shared is machinery, not content. One stylesheet (assets/site.css), one nav component, one pipeline shape, one release discipline — copied deliberately rather than packaged, so any site can diverge without asking permission. What is not shared is a single word of argument: each site is written from its own documents.

This site's place in it

The network has a shape, and this site is the layer underneath it. The other sites teach an agent what the project thinks and how the estate works. This one is for where the thinking came from — so that an agent extending the estate extends its instincts deliberately rather than by accident.

The deconfliction rule, and why this site needs one badly

Several of the influences on this site already have an entire sibling site. Wardley mapping has one. Graphs have one. Open source has one. If the influence entry for Wardley tried to explain Wardley mapping, this site and that one would be making the same argument slightly differently — which is the real failure mode for a network of sites, and much worse than a dead link.

So the rule is a split, and it is enforced by the entry format rather than by good intentions:

This site owns

  • The resonance. Why this, and why it landed — in first person, which is the house style here and nowhere else in the network.
  • The personal history. Where the influence entered, and when.
  • The trace pointer. "The trace of this influence is an entire site" — and a link.

The sibling owns

  • The material. The maps, the grammar, the licences, the history pack.
  • The teaching. How the thing works, for someone who wants to use it.
  • Its own release history, its own gaps and its own open questions.

An entry that grows past resonance-and-trace has scope-crept into a sibling. When that happens the material moves to the sibling and the entry keeps the pointer — a rule that is easy to write and needs enforcing at review time, because the pull is always in the other direction.

What every site in the network runs

The same three jobs, in the same order, gated the same way — described in full on this site's engineering page:

validate ──▶ tag-release ──▶ deploy
#  a failure in any job stops the ones after it; the live site is never
#  replaced by a release that did not pass its own checks

The differences between sites are the checks each one adds, and the addition is always the site's own subject made executable. sg-compute.sgit.ai bans live hostnames and instance ids because it documents running infrastructure. coding.sgit.ai fails a release if a code example has drifted from the survey it was quoted from, because a style guide with stale examples is worse than none.

This site adds two. The no-verbatim gate caps a third party's quoted words at forty, because this is the one site in the network whose subject matter belongs to other people. And the register-is-the-data check recomputes every tier count from the register on every build, because tier movement is this site's changelog and a hand-typed count is what makes a change invisible.
